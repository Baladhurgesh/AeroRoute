# AeroRoute project facts

## Data acquisition
- Use Python 3.11+ and curl; raw acquisition uses only the Python standard library. Developed and tested with Python 3.14.3 on macOS.
- The selected dataset is BTS Marketing Carrier On-Time Performance, January 2020 through December 2025, not the Reporting Carrier table.
- All 72 original monthly archives are downloaded and passed full offline checksum/ZIP/CSV verification: 40,910,253 records and 2,163,774,074 compressed bytes. An idempotent rerun skipped all 72 valid archives without downloading them again.
- Source archive directory: https://transtats.bts.gov/PREZIP/.
- Preserve original monthly ZIPs under `data/raw/bts_marketing/{year}/`; data is excluded from Git. Do not extract all CSVs to disk.
- `manifest.json` in the data directory records source metadata, SHA-256, original CSV headers, dates, row counts, and cancellation/diversion counts. Local hashes are not BTS-published signatures.
- Run only one downloader per output directory. Reruns skip checksum-validated completed files and restart incomplete monthly transfers. Conflicting completed files are not overwritten.
- Real BTS headers can include `Operating_Airline ` with trailing whitespace and an empty trailing column. Validation normalizes names for presence checks but preserves original records and headers.
- Required headers include both flight numbers, cancellation code, actual clock times, diversion landing count, and airport codes/IDs/wheels-on/wheels-off for all five diversion stops. Header presence does not imply a non-null value on every flight.

## Commands
- Full project tests (including PyArrow-dependent components): `uv run python -m unittest discover -s tests -v`
- Live source/disk preflight without writes: `python3 scripts/download_bts.py --dry-run`
- Single-month pilot: `python3 scripts/download_bts.py --start-year 2020 --end-year 2020 --month 1`
- Download or resume all 72 months: `python3 scripts/download_bts.py --start-year 2020 --end-year 2025`
- Full local validation without network or writes: `python3 scripts/download_bts.py --start-year 2020 --end-year 2025 --verify-only`
- Override destination with `--output-dir /absolute/path`. Defaults are anchored to the project, not the shell working directory.

## Constraints for later preprocessing
- Keep cancellations and diversions even when ordinary arrival fields are null. Use 2020–2024 for historical fitting and keep 2025 outcomes isolated for evaluation.
- Obtain an airport-to-IANA-timezone lookup before reconstructing timestamps. Handle local dates, midnight rollover, DST, and missing/ambiguous timezone mappings explicitly.
- Scheduled arrival UTC can be derived from dated scheduled departure UTC plus CRSElapsedTime, with local arrival clock fields used for cross-checks.
- Div1Airport is not necessarily the final diversion airport. Inspect DivAirportLandings and all available diversion stops.
- DivActualElapsedTime and DivArrDelay apply to diverted flights reaching their scheduled destination. If a stranded diversion's timeline cannot be reconstructed reliably, terminate with a documented unresolved-timing reason; do not invent a timestamp.
- Weekday and departure-time buckets can be derived from FlightDate and CRSDepTime. Delay-cause fields are retained in raw archives but are not required for empirical outcome sampling.

## Episode record contract
- `aeroroute.records` exports five primary frozen dataclasses: TripRequest, FlightOption, FlightOutcome, DecisionStep, and EpisodeRecord, plus typed settings/provenance/airport/diversion/terminal helpers. Construction validates types and invariants; collections are immutable tuples.
- `start_at` means the traveler is present at the origin, not already boarding-ready. The initial decision is at start_at. All record timestamps must already be dated UTC; local-clock reconstruction stays in preprocessing.
- For a resolved normal or diverted arrival, `next_decision_at == actual_arrival_at`. Arrival is before the connection buffer. The next step's `decision_at` is this timestamp; `ready_to_board_at` is decision_at plus exactly one connection buffer.
- Settings separately define initial boarding buffer (default 60 minutes), connection buffer (45), and cancellation boarding buffer (0). These are configurable modeling assumptions, not BTS-observed quantities.
- For cancellation, `next_decision_at` is the modeled recovery/notification time, not an arrival timestamp. Apply only cancellation_boarding_buffer_minutes afterward; do not apply the initial or connection buffer again. The environment must record the recovery policy/version in timing_method and its parameters in EpisodeProvenance.transition_parameters; record validation does not invent this time or enforce an unimplemented recovery formula.
- Scheduled departure must meet readiness at selection. Every known actual departure must also meet readiness; impossible early historical departures are rejected, not clamped. The future environment must explicitly decide how to handle unboardable sampled outcomes rather than silently resampling away their risk.
- `episode_end_at` is derived from start_at plus max_duration_minutes. arrival_deadline is a grading target, not a stopping rule. Arrival exactly at the hard cutoff is allowed; new selections at the cutoff and observed outcome events after it are not.
- If a cutoff interrupts a flight, censor unobserved completion fields and use unresolved_reason=`episode_cutoff` with termination_reason=`time_limit`. OutcomeStatus.UNRESOLVED covers unclassified/in-flight outcomes; a known diversion may retain its status and observed stops while its final airport/time remain null. A timeout while waiting at a known airport may advance the terminal clock to the cutoff.
- `TerminalState.last_known_at` is the last known trace timestamp, not necessarily the arrival time at TerminalState.current_airport. Unknown next_decision_at stays null; no further action is allowed after an unresolved outcome.
- Flight arrival delay is defined only if reached_scheduled_destination is true and actual_arrival_at is known. Trip lateness is separately derived against the requested trip destination/deadline. A diversion to the trip destination can complete the trip even if it did not reach that leg's scheduled destination.
- Do not store a success flag or reward in the trace. Arrival time, lateness, cancellation counts, and diversion counts are derived. Invalid actions raise validation errors; no invalid_action or immediate-cancellation terminal behavior has been implemented.
- Store full details only for the selected flight, with compact offered-flight IDs and a shared immutable schedule reference. Selected instances cannot be attempted twice. No-feasible-flights claims and authenticity of offered IDs still require reconstructing the search against that schedule and recorded settings; these records provide consistency checks, not proof of authenticity.

## Provenance and serialization
- SourceRecordRef.source_row_id is the 1-based ordinal of the original CSV data record, excluding the header, within csv_member of the archive identified by source_sha256. It is not a filtered DataFrame index or a physical text-line number. Preserve it during ingestion.
- dataset_version/outcome_dataset_version are lowercase SHA-256 identifiers of a frozen dataset inventory snapshot; freeze the inventory before simulation rather than hashing the changing download-progress manifest on each step. Snapshot materialization belongs to the preprocessing phase.
- ScheduleRef stores a snapshot name and content SHA-256. HistoricalSampleRef separately stores its source, original flight date, pool ID/size/fallback level, and matching_pool_sha256 identifying the ordered pool membership. A source row index or seed without these references is insufficient for reproducible sampling.
- EpisodeProvenance stores simulator/sampler versions, seed, schedule identity, outcome dataset identity, and immutable string key/value tuples for sampler and transition parameters. Referenced snapshot/pool objects must be retained and checked by the later data-access layer.
- Use `EpisodeRecord.to_dict()/from_dict()` and `to_json()/from_json()` for portable records. JSON uses UTC ISO-8601 strings, enum strings, arrays, and explicit nulls; decoding restores typed tuples/dates/enums and reruns validation. Unsupported schema versions, unknown/duplicate fields, and coerced scalar types are rejected.
- Test records alone: `uv run python -m unittest discover -s tests -p test_records.py -v`. Run all tests with the command above.

## Preprocessing pilot
- The approved milestone normalizes only explicitly selected months, not the full 72-month range. The pilot is January/March/November 2020 and January 2025. Wait for review before full-range preprocessing or expanded revision-management commands.
- Dependencies are pinned in pyproject.toml/uv.lock: PyArrow 25.0.1, airportsdata 20260905, tzdata 2026.4. uv selected a project-local CPython 3.12.11 environment; the standalone raw downloader also works with system Python 3.14.3. The global interpreter was not modified.
- Pilot command: `uv run python -m aeroroute.preprocessing --periods 2020-01 2020-03 2020-11 2025-01`. Use --raw-dir/--output-dir for alternate roots, --batch-size for bounded batches, --airport-overrides for reviewed mappings, and --verify-only for a completed partition compatible with the current transform fingerprint.
- Experiment membership is manifest-only, configurable with --historical-years and --evaluation-years; defaults remain 2020–2024 versus 2025. Adding source years does not automatically move a holdout boundary.
- Normalization uses strict csv.reader with the downloader's record-counting semantics, then explicit Arrow output schemas. Bad numeric cells become typed null plus raw-value diagnostics. Integral decimal strings are accepted; fractions are never silently truncated. No cancelled, diverted, duplicate-flagged, or unresolved row is filtered out.
- Each timestamp is an independent TimeFact structure: value, status, method, issues, checks, evidence. Arrival can be resolved from either actual departure + actual elapsed time or scheduled arrival + arrival delay. Destination-reaching diversions use the corresponding Div fields. Two available paths must agree within the configured tolerance, default zero minutes. Missing evidence and contradictory evidence are reported separately.
- ZoneInfo is loaded explicitly from pinned tzdata resources, never implicitly from host TZPATH. Airport mapping checks exact codes and state evidence; current-reference conflicts remain flagged pending review. No airport overrides were applied to the pilot.
- Scheduled 2400 date anchoring remains conservatively unresolved pending a verified field-specific convention. Observed 2400 clocks can be compared as midnight only when independent timestamps/date bounds already provide the date.
- Diversion wheels-on/off facts are separate from gate arrival and boarding readiness. Without reliable lower/upper date anchors, stop timing remains unknown. No taxi/deplaning/recovery time is invented. The 366-day search guard emits an explicit resource-limit issue; it never chooses a convenient date.
- Reusable immutable partitions live under data/processed/partitions/year=YYYY/month=MM/<fingerprint>/. Dataset manifests reference exact partitions and contain independent source inventories. Existing files are never overwritten on conflict. New code/reference versions produce new partitions; old snapshots remain auditable.
- Audit/report command: `uv run python -m aeroroute.pilot_report --dataset-dir data/processed/datasets/aaa7c8557aafe6d6c2f45b38cbdcb55f85462d9ad3cd5fa9d732cd102b187349`. This calls verify_dataset, verifies referenced artifacts, independently scans Parquet source ordinals and disruption flags, and emits data/reports/<snapshot>/pilot_review.json without changing the snapshot.
- The verified pilot snapshot contains 2,350,430 rows, 147,538 cancellations, and 4,071 diversions. Its monthly Parquet files total 249,019,574 bytes; observed normalization took about 177 seconds in total with a maximum reported process high-water mark of 173,309,952 bytes. Memory readings are process-lifetime peaks, not per-month allocations.
- Pilot mapping conflicts affect 137,618 flight rows. Main findings: airportsdata labels DCA/IAD as District of Columbia while BTS says Virginia; territory subdivision labels also differ. These require reviewed reference reconciliation, not silently dropping flights or guessing timezones.
- All 768 stranded-diversion records are retained with endpoint evidence, but their gate-arrival timestamps remain unresolved. Multi-stop/reached-destination examples and every time-resolution issue category are included in the review report. All four pilot months have the same raw header schema.
- Month reuse was exercised on real partitions (roughly 0.1–0.3 seconds per cached month) and covered by tests asserting no CSV rescan. Source hashes, row ordinals, and output checksums are preserved.
- Current pilot fingerprints conservatively hash supporting module source, so unrelated edits to shared helper modules can invalidate reuse even when normalized facts are unchanged. Artifact verification of an old snapshot is still valid; lack of a current-compatible cache entry is not corruption. Narrower dependency fingerprints are a later refinement.
- Normalized snapshot versions currently identify exact partition manifests/artifacts, including quality-report telemetry through their checksums. Fresh rebuilds can therefore yield a different normalized snapshot version even with identical raw inventories. Raw inventory identities and source-record IDs remain content-stable; separate logical-data identity from run telemetry before broader revision management.
- Do not interpret performance on 2025 schedules with 2020–2024 sampled outcomes as actual 2025 performance evaluation. The later evaluator must specify how held-out realized outcomes are used. Year weighting is also a later pool-policy decision.
- Preprocessing tests: `uv run python -m unittest discover -s tests -p test_preprocessing.py -v`.

## Service catalog and outcome providers
- `data_access.DatasetStore` verifies a normalized snapshot and its separately hashed source inventories. `SourceRecordRef.dataset_version` identifies an inventory, not the normalized snapshot digest. Selected fitting inventories can cover a strict subset of historical years.
- Build inspection artifacts with `uv run python scripts/build_data_access.py --snapshot /absolute/path/to/dataset_manifest.json --stage inspect`. The default output is project-anchored `data/processed/access/`. `--dry-run` verifies inputs without writes; `--verify-only --artifact /absolute/path/to/artifact` verifies lookup/services or complete pilot artifacts without rebuilding.
- `source_record_id` remains the archive/member/original-CSV-ordinal identity. `service_instance_id` is a schedule-only, versioned identity; `FlightOption.flight_id` uses that service identity. Supporting source records are retained in the catalog; `schedule_source` is its primary schedule reference.
- The initial `exact-operating-service-v1` resolution policy groups matching dated operating departures, checks schedule conflicts and marketing/original-service aliases, and rejects ambiguous groups. `Duplicate=Y` is never a generic deletion instruction. A nonempty cited `--review-reference` records external pilot review; it is not automatically supplied by the builder. Schedule/evidence conflicts still prevent readiness after review. New authority/override rules require a separate reviewed policy, not an arbitrary source preference.
- The catalog's retained source/stop lookup maps immutable record IDs to artifact-hash-bound Parquet file, row group, and within-group row offset. Physical offsets never replace original CSV ordinals. Runtime lookup uses projected row-group reads with byte-bounded LRU and file-handle limits; queries do not build indexes or scan monthly Parquet files.
- `ScheduleStore.departures` uses inclusive readiness and exclusive departure upper bounds. It never filters by observed outcomes or by scheduled arrival versus deadline. Queries are complete relative to the published schedule-eligibility policy, not proof of complete real-world schedule coverage. Unknown timezone/period coverage raises rather than returning an empty offer set.
- Departure queries return bounded pages (default 1,000; maximum 10,000). Follow `next_cursor` until `complete` is true; cursors bind the snapshot, airport, window, and attempted service set. Attempting a service excludes all its aliases. Schedule shards are sized independently of airport/date lookup keys.
- Pools weight resolved historical services uniformly, not supporting-row multiplicity. A retained pool binds ordered service/source membership, fitting inventory, matching hierarchy, and resolution policy. `matching_pool_size` counts services. Source evidence is never independently mixed, re-dated, filtered by traveler readiness, or resampled to avoid cancellations/diversions/unresolved observations.
- Matching defaults are provisional: six-hour local scheduled-departure buckets, 30-service support target, and progressively relaxed route-preserving criteria. `--retain-time-of-day` relaxes quarter before time bucket. `PreparedPools.validation_report(service_ids)` reports request-weighted fallback/carrier/time-of-day/low-support/unsupported rates and rejects 2025+ or fitting-year requests. Coverage reports on held-out schedule attributes are not permission to tune on held-out outcomes.
- `Scenario` binds a pool set and schedule. Seed, scenario ID, selected service ID, membership identity, and sampler version generate the draw using SHA-256 rejection sampling. Episode labels and step indices are trace-only. The same frozen scenario/service gives the same evidence across policies and query order.
- Exact replay has separately prepared singleton membership mappings and returns the held-out departure's authoritative evidence, including incomplete observations. It never falls back to fitting pools. Schedule identity conflicts or conflicting supporting observations block readiness; missing observation fields alone do not.
- After review, the synthetic/live-path entry point is `uv run python scripts/build_data_access.py --snapshot /absolute/path/to/dataset_manifest.json --stage pilot --review-reference REVIEW_ID --schedule-periods 2025-01 --fitting-years 2020`. It queries a held-out departure, reproduces a fitting-only draw at two trace steps, retrieves replay evidence, retains scenario/receipts, and measures cold-application-cache and warm lookups. Use `--service-id` to choose a particular departure. The default first held-out departure is not silently replaced if its pool is unsupported.
- Providers return historical evidence, not traveler transitions. Timestamp transfer, cancellation recovery, early-departure handling, cutoff censoring, environment rewards, and verifier scoring remain unimplemented. Replay claims must remain historical replay under explicit traveler/recovery assumptions, not proof of seat availability or real passenger rebooking feasibility.
- Data-access tests: `uv run python -m unittest discover -s tests -p 'test_data_access*.py' -v`; additionally run `test_service_resolution.py`, `test_schedule.py`, and `test_sampling.py`, or the full project suite above.
